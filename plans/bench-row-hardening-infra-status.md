# bench-row-hardening-infra-status — a dead server never writes a junk row again (#2)

You are phase `infra-status` of the `bench-row-hardening` plan. You make
infrastructure failures structurally distinguishable from model failures in
`run_eval.sh` and `run_bigdiff.sh`: a footer-based allowlist decides whether a
run was a measurement at all, a pre-dispatch probe aborts the batch instead of
writing a cascade of junk rows, and the `status` column added in phase `schema`
starts carrying values.

## Locked decisions (do NOT re-litigate)

See `plans/bench-row-hardening.md` and `docs/bench-hardening-spec.md`. Summary:

- **Allowlist, not blocklist.** The audit footer is emitted before all five
  audit exit paths, so *footer present ⇔ a measurement happened*. #2's
  two-signature grep would still have missed the third failure from the same
  night (the exit-127 splice).
- **Classifier precedence, and the order is load-bearing:**
  1. `rc == 124` → `status` **empty**. The watchdog kills `review.sh` *before*
     its audit block, so a timed-out run has no footer; a naive
     footer-absent rule would misclassify it as infrastructure.
  2. audit footer present → `status` **empty**.
  3. footer absent AND an anchored `^local-review: ` grep of the `.err` matches
     the reachability or lock signature → **terminal row + abort the batch**.
  4. otherwise → `SUSPECT`.
- **A pre-dispatch refusal writes NO per-run row.** The batch writes exactly
  ONE terminal row whose `status` is the cause (`SERVER-DOWN` or `LOCKED`) and
  aborts. Zero rows would make a truncated arm indistinguishable from a
  deliberately short one; a per-run cascade is the 14-junk-rows incident itself.
- **The terminal row MUST NOT occupy a dispatchable key.** Write a reserved
  non-numeric token (`abort`) in the `run` column, and leave `case` / `item`
  empty. Dispatch keys always carry a numeric `run`, so phase `resume`'s
  key-existence check can never match a terminal row — which is what keeps
  resume free of any status inspection and stops an aborted batch from
  permanently poisoning the key it failed on. Getting this wrong reintroduces
  the exact #1-vs-#2 deadlock this whole workstream was designed to dissolve.
- **Distinct exit code** for the infrastructure abort, separate from the
  existing exit 2 (which means "fixture invalid, do not resume"). The new one
  means "infrastructure, nothing recorded, re-run the identical command".
- **Anchor the grep on `^local-review: `.** Model-derived free text reaches
  stderr (verdict reasons under `--json`, a single-word flag reachable through
  the runners' arg passthrough), and a reviewed diff could contain the phrase
  literally.
- **Never retype the signature strings** — extract them from `review.sh` in a
  drift test.
- `SUSPECT` is the **open bucket and is not optional**. OOM, pi crash,
  model-unload race and disk-full all land as a plain `rc != 0`; a blank
  `status` that a reader trusts is worse than an explicit unknown.
- The probe proves a port answers, **nothing more**. Probe only between runs;
  retry before declaring down.
- **Any new env override goes into `run_ctx_tiers.sh:25-26`'s unset list**, in
  this phase, with a test.

   - **Lock refusal.** Stub that prints `review.sh`'s real lock refusal to

   - **Server down at batch start.** Point the URL override at a closed port →
     the new exit code, the results file gains exactly one terminal row, and no

   - **Server dies mid-batch.** Start a throwaway listener, point the override

     pins the precedence order.

     audit footer → `status` empty (it was a measurement). A stub that exits

## Failure modes to watch

- **Checking the footer before `rc == 124`.** A timed-out run has no footer
  because the watchdog kills `review.sh` before its audit block runs. Get this
  backwards and every timeout is misfiled as infrastructure — and under phase
  `resume` that would make timeouts retryable, silently deleting the slow tail
  from every arm's latency distribution.
- **Grepping without the `^local-review: ` anchor**, or grepping stdout instead
  of stderr. The reviewed diff can contain the signature text.
- **Retyping the signature strings** into the runners. The drift test is what
  makes them safe to depend on; without it the greps rot silently the next time
  `review.sh` rewords.
- **A single-shot probe with a short timeout.** `run_ctx_tiers.sh:112-120`
  retries for twenty minutes precisely because a loaded machine mid-prefill
  does not answer promptly. Killing a healthy 40-minute arm on a false negative
  is self-inflicted evidence loss.
- **Writing a marker into `found` or `found_any`.**
  `bench/summarize_ctx_tiers.py:55` int-casts `found`; a token there is a
  `ValueError`, not a marker.
- **Treating the probe as safety.** It proves a port answers. The footer
  allowlist must still fail closed as if no probe existed.
